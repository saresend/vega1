    03what is this

    Vega1 is a local System 1 model for video. "System 1" is the fast type of human thought that gives an immediate answer. "System 2" is the slow type of thought that examines a problem step by step.

    Vega1 operates as a System 1. It does not write text, and it does not show its steps. It examines a video one time. Then it answers all of your questions in one step. Each answer is the probability that the statement is true.

    Vega1 uses the same structure as the TypeSafe Jev System One API. You give a state and typed questions. The model gives typed answers. In this model, the state is a video.

    The full Vega1 model operates on your device, in this browser tab. It operates on a laptop or on a phone. The model does not send the video or your questions to a server.

    This page shows yes/no statements. For choice questions (select one option from a set), use Vega1-cat.

    04how it works

    ┌─ your browser ────────────────────────────────────────────┐
│                                                           │
│  video ──────────> image encoder ──> frames ─┐            │
│                                              ├──> p(yes)  │
│  "there is a dog" ──> text encoder ──> text ─┘            │
│                                                           │
└───────────────────────────────────────────────────────────┘
    • frames The model takes 16 frames from the video. The MobileCLIP-S0 image encoder (11 million parameters) makes an embedding of each frame. The model also examines 6 close-up crops of 4 frames to find small details.
    • statements The text encoder (42 million parameters) makes an embedding of each statement. For a negative statement ("there is no dog"), the model answers the positive statement and gives the opposite answer.
    • answer head An attention head with 1 million parameters examines the frames and the statement. It gives the probability that the statement is true. We trained the head on 134,000 statements with labels. These statements are about objects, scenes and captions from COCO and activities from UCF-101. Other statements are about subtitles, watermarks and graphics that we added to videos.
    • speed The model embeds a video one time. This takes a few seconds. After that, each question takes approximately 20 milliseconds. The model is Rust code that we compiled to WebAssembly. It uses all the processor cores that the browser makes available.

    05limits

    • The model can miss very small objects, also with the close-up crops.
    • The model cannot count exactly. It can identify "exactly one person" or "a group".
    • Text on the screen can change the answers, because the encoder reads the text.
    • The model examines only the sampled frames. It does not see events between these frames.
    • In unusual scenes, the model can give an answer from things that usually occur together. Example: "grass" on a street with snow.
